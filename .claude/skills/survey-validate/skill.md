# Survey Specification Validator

Validates a generated table specification document against schema, variable references, and business logic.

## Overview

This skill validates a `table_specification.json` file generated by the `survey-spec-gen` skill or created manually. It checks:

1. **Structure** - JSON schema compliance
2. **References** - All variables and indicators exist
3. **Logic** - Business rules and consistency
4. **Syntax** - PSPP compatibility

## When to Use

Use this skill when:
1. After generating a table specification with `survey-spec-gen`
2. Before running analysis computations
3. When manually editing a specification

## Input Requirements

The skill requires:
1. **Table specification JSON** - The specification file to validate
2. **Filtered metadata** - Variable metadata from the SPSS file (for reference validation)

## Output

Produces a validation report with:
- **Errors** - Critical issues that must be fixed
- **Warnings** - Potential issues to review
- **Summary** - Overall validation status

## Validation Checks

### Structure Validation

- Required sections exist (metadata, tables, output_settings)
- Required fields present in each table (id, title, type)
- Valid enum values (table types, metric types, aggregation types)
- No duplicate table IDs or indicator IDs

### Reference Validation

- All referenced variables exist in the SPSS data
- All referenced indicators exist in the specification
- Weight variables are valid
- Recoded variables reference valid source variables

### Logic Validation

- Significance threshold between 0 and 1
- Cramer's V minimum between 0 and 1
- At least one table defined
- Output settings are reasonable

### Syntax Validation

- Recoding rules match their declared type
- Crosstab tables have at least one dimension
- Metrics are appropriate for table type
- PSPP syntax is compatible

## Example Usage

```
Validate this table specification:

Specification file: table_specification.json
Metadata file: output/filtered_metadata.json
```

## Exit Codes

- **0** - Specification is valid (no errors)
- **1** - Specification has errors (must fix before processing)
